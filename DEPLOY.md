# Deploying

Target: **GitHub repo + Cloudflare Pages**. The repo *is* the deploy
artifact — build output is committed; Cloudflare runs nothing.

## First deploy

Cloudflare Dashboard → Workers & Pages → **Create → Pages →
Connect to Git** → pick this repo:

| Setting          | Value        |
|------------------|--------------|
| Production branch| `main`       |
| Build command    | *(none — leave empty)* |
| Build output dir | `/`          |

`_redirects` (committed, generated by build.py) handles `/` → `/en/`
plus bare-section conveniences; the committed root `index.html` is the
no-redirect fallback. `404.html` is picked up by Pages automatically
and self-localizes from the URL's language segment.

## Custom domain

Pages → Custom domains → add `orbandink.co.uk` (and `www`, set to
redirect to the apex). Then update `domain` in `data/site.csv` if it
ever changes and rebuild — canonicals, hreflang, OG URLs and
sitemap.xml all derive from it.

## Every update after that

    # edit data/*.csv (and covers/)
    python3 build.py
    git add -A && git commit -m "content: …" && git push

Pages redeploys on push. Nothing else to configure.

## The worlds ride along

Each series site is mounted under `worlds/<slug>/` by
`tools/sync_worlds.py` (see README), so this one deploy also publishes
`orbandink.co.uk/worlds/the-calorate/` and the rest. To give a series its
own domain later: deploy its folder as its own Pages project, put that
address in `data/series.csv`, delete `worlds/<slug>/`, rebuild.

## Announcing a book (the release checklist)

The whole shelf is on show: `catalog_coming_soon` in `data/site.csv` is
`show`, so all forty-five books and all twelve series are built, the
unreleased ones saying so on their own pages. Set it to `hide` to build
only books with status `preorder` or `published` (and only their
series).

**Per book, when its date is known** (all in `data/books.csv`):

1. `release_date` — ISO `YYYY-MM-DD`. It renders as a localised line on
   the book plate (`1 October 2026`, `1er octobre 2026`, `2026年10月1日`)
   and as JSON-LD `datePublished`. Leave it blank and the row simply
   does not appear, which is the right look for an unannounced book.
2. `status` — `coming_soon` → `preorder`. A pre-order whose
   `release_date` has passed is built as published automatically, so
   nothing needs editing on the day (set `published` by hand for a book
   with no date). The pill, the call to action and schema.org
   availability all follow from this one field.
3. A row in `data/store_links.csv` for each retailer. **A dated book
   with no link is a dead button**, which the series briefs forbid; the
   buy block falls back to a "coming from Orb & Ink" state without one.
4. `isbn` once assigned, and `pages` from the book's own
   `build/print_report.json` — never typed by hand, and only for a book
   whose chapters are all `final`. A page count taken from a draft
   drifts, and the same figure sets the spine width on the cover.

Then the usual `python3 build.py`, commit, push.
